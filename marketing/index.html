How it works

Three steps, one committed JSON report.

01

Read

Finds your OpenAPI spec, scans your tests. No configuration.

02

Compare

Matches every documented response to the assertions that check it.

03

Guard

The report is one committed file. CI fails when it goes stale.

What it expects

Suites titled with method and path, status assertions, prettier-consistent formatting. Tests written another way are reported as untested, never guessed.

tasks.test.ts Suites titled with method and path 
describe("POST /tasks", () => {
  it("creates a task", async () => {
    const res = await api.post("/tasks", body);
    expect(res.status).toBe(201);
  });
});
openapi.json The documented response it is matched against 
"paths": {
  "/tasks": {
    "post": {
      "responses": {
        "201": { "description": "Task created" }
      }
    }
  }
}
tasks.test.ts {taskId}, [taskId], and :taskId are the same parameter 
describe("GET /tasks/:taskId", () => {
  it("returns a task by id", async () => {
    const res = await api.get(`/tasks/${id}`);
    expect(res.status).toBe(200);
  });
});
tasks.test.ts toBe or toEqual, both count 
it("returns 404 for an unknown id", async () => {
  const res = await api.get("/tasks/task_missing");
  expect(res.status).toEqual(404);
});
other.test.ts Not matched. Reported as untested, never guessed 
it("creates a task", async () => {
  const { statusCode } = await api.post("/tasks", body);
  assert.equal(statusCode, 201);
});

Get started

Install as a dev dependency and run it from your repo.

Terminal · npm, pnpm, yarn, or bun 
$ npm install -D specproof
$ npx specproof dev
→ localhost:3001

On CI

Commit the report next to your code.
specproof generate --check exits 1 when the report is out of date.

.github/workflows/specproof.yml 
name: specproof
on: [pull_request]

jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
      - run: npm install
      - run: npx specproof generate --out specproof.json --check
