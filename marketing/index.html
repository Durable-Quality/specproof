02

Method

generate → checked-in artifact → contract test
GENERATE

Read both sources of truth.

The analyzer reads the target repo's OpenAPI spec — auto-discovered as the shallowest openapi*.json / swagger*.json, or pinned with SPECPROOF_SPEC — and every test suite titled describe("METHOD /path"), matching .status).toBe(NNN) assertions to documented responses. {param}, [param], and :param segments are treated as equivalent.

COMMIT

One deterministic, checked-in artifact.

The result is app/proof.generated.json — regenerated before every dev and build, committed alongside your code. The app renders only the artifact, so building and deploying the audit needs no target checkout at all.

ENFORCE

A contract test keeps the proof honest.

app/proof-contract.test.ts fails CI when the artifact is stale relative to the spec or tests, when the audited operations drift from the spec's, or when a quoted snippet no longer points at a real it() block. The proof cannot silently rot.

03

Quickstart

requires bun
TERMINAL 
$ git clone https://github.com/Durable-Quality/specproof.git specproof
$ cd specproof && bun install
$ SPECPROOF_REPO=/path/to/your-repo bun run dev
→ compiles the proof, then serves it on http://localhost:3001

SPECPROOF_REPO defaults to the current working directory — run it from inside the target repo and it needs no configuration at all.

When the target's spec or tests change, bun run generate:proof refreshes the artifact; commit it and CI goes green again.

Conventions, commands, and the drift guard are documented in the README.
